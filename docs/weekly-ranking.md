# 주간 맛집 랭킹 도메인·운영 명세

## 집계
- 한국 시간 월요일 00시~일요일 24시. 매시간 5분에 집계합니다.
- 조회 1점: 로그인 회원이 실제 후기 화면을 표시했을 때 회원·식당·하루 1회. 페이지 미리 불러오기, 비로그인, 본인 후기 조회는 제외합니다.
- 좋아요 3점: 이번 주 새 좋아요, 회원·식당·주간 1회. 다른 후기에 여러 번 눌러도 1명입니다. 본인 후기 좋아요는 제외합니다.
- 북마크 5점: 이번 주 새 저장, 회원·식당·주간 1회. 식당 등록자도 다른 사람과 동일하게 저장할 수 있습니다.
- 이번 주 취소는 점수를 제거하고 재등록은 같은 1회로 복구합니다. 이전 주부터 계속 유지한 좋아요·북마크는 신규 점수가 아닙니다.
- 서로 다른 회원 3명 이상이 반응한 식당만 순위에 진입합니다. 조회·좋아요·저장의 참여자는 합집합으로 계산합니다.
- 동점: 북마크 참여자 → 좋아요 참여자 → 조회 참여자 → 식당 ID 순서로 안정적으로 정렬합니다.
- 폐업·삭제 식당, 숨김·삭제 후기 제외. 현재 순위는 다음 집계에서 반영하며 폐업·삭제 식당은 조회 시에도 즉시 제외합니다.
- 지난주 결과는 처음 확정한 뒤 점수를 수정하지 않습니다. 당시 기록은 보존하며 현재 공개할 수 없는 식당은 표시하지 않습니다.
- 첫 도입 전 누적 수치로 과거 주간 통계를 만들지 않습니다. 첫 주 또는 참여 부족 시 집계 대기를 표시합니다.

## 구현과 권한
- `ranking_signal`, `ranking_control`, `ranking_week`, `ranking_entry`, `ranking_run` 5개 테이블을 추가합니다. 기존 회원·후기·사진을 변경하거나 삭제하지 않습니다.
- 반응 변경과 랭킹 기록은 같은 트랜잭션에서 처리합니다. 고유 키와 집계 잠금으로 중복 및 동시 요청을 제어합니다.
- 조회 기록은 인증된 `POST /posts/{id}/ranking-views`; 본인/회원 ID 및 식당은 서버에서 결정합니다.
- 공개 조회: `GET /rankings/weekly?period=current|previous&office=...`.
- 관리자만 `GET/POST /admin/ranking-runs` 접근 가능. 매니저는 관리 기능에 접근할 수 없습니다.
- 수동 집계는 현재 주·미확정 과거 주차를 재처리합니다. 실패하면 기존 결과를 유지하고 이력을 기록하며 다음 정시 실행에서 재시도합니다. 실패 원인은 서버 로그에서 확인합니다.
- 중단된 RUNNING 이력은 다음 집계에서 1시간 경과 시 실패로 정리합니다. 현재 버전에는 신호 이력 자동 삭제가 없습니다.
- 이상 반응 목록은 최근 24시간 유효 신호 100건 이상 회원을 관리자에게만 보여줍니다. 자동 제재나 점수 삭제는 하지 않습니다.

## 화면과 체험판
- 홈 TOP 3, 맛집탐방 > 주간 맛집 랭킹(`/ranking`), 관리자 전용 서비스 관리 > 주간 랭킹 관리(`/admin/ranking`).
- PC 3열·모바일 1열, 대표 사진·순위 변동·주간 수치·후기 연결, 이번 주/지난주와 본사·지사 선택 제공.
- Vercel은 `scripts/export-ranking.cjs`로 공개 집계 API만 정적 JSON으로 내보냅니다. 회원 ID·개별 활동 기록·DB 파일은 내보내지 않습니다.
- 정적 자료에 기준 주차를 표시하며 체험판 클릭은 운영 순위에 반영되지 않습니다. 자격을 충족한 운영 식당이 없으면 사실대로 빈 상태를 표시합니다.

## 검증 시나리오
- 동일 조회 재전송·여러 후기 조회·동시 조회: 하루 1점.
- 같은 식당 여러 후기 좋아요: 주간 3점. 취소/재등록으로 추가 증가 없음.
- 기존부터 유지한 북마크: 신규 점수 없음. 이번 주 새 저장 5점, 취소 시 제외.
- 회원 2명만 참여: 미진입. 서로 다른 3명: 진입.
- 일요일 23:59:59와 월요일 00:00:00: 서로 다른 주차.
- 관리자 재집계 성공·실패·복구 및 지난주 확정 점수 보존.
- 일반 회원·매니저의 관리 API 접근 차단.
- PC·모바일 랭킹·홈·후기 연결·필터·빈 상태·관리 화면.
